# PRISM

[![tests](https://github.com/VeniVidiVici-KR/Prism/actions/workflows/tests.yml/badge.svg)](https://github.com/VeniVidiVici-KR/Prism/actions/workflows/tests.yml)

월가아재의 Valley AI(valley.town)에서 아이디어를 얻은 개인 투자 리서치 앱.

핵심 흐름: **티커 입력 → 회사 개요·주가·재무 추이 확인 → Peer Group/PER·PBR 비교 → 업종에 맞는 밸류에이션(제조업 DCF / 금융업 P·B×ROE·DDM) → 공시 확인 및 AI 한국어 요약 → AI 해설**.

한국 종목은 DART 공시·KRX 투자자별 수급까지, 미국 종목은 SEC EDGAR 공시 목록·본문 요약까지 함께 본다. 별도의 "Macro Indicator" 페이지에서 미국/한국 매크로 지표(물가 구성항목·기여도 분해, 금리, 고용, 재정 등)를 비교한다.

## 설치

```bash
pip install -r requirements.txt
```

## 설정

`.env.example`을 `.env`로 복사하고 필요한 키를 채워넣는다.

```bash
cp .env.example .env
```

```
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=
OPENAI_MODEL=gpt-4o-mini
GEMINI_API_KEY=
GEMINI_BASE_URL=
GEMINI_MODEL=
ECOS_API_KEY=...
DART_API_KEY=...
KRX_ID=...
KRX_PW=...
BLS_API_KEY=...
KOFIA_API_KEY=...
TOSS_CLIENT_ID=...
TOSS_CLIENT_SECRET=...
```

API 키가 하나도 없어도 재무 데이터 조회와 DCF 계산은 정상 동작한다. 각 키는 특정 기능에만 필요하며, 없으면 그 기능만 안내 메시지로 대체되고 앱 전체가 죽지는 않는다.

### AI 엔진 (OPENAI_* / GEMINI_*)

AI 해설·공시 요약·회사 개요 요약에 쓰인다. 사이드바의 "AI 엔진" 라디오로 **학교 게이트웨이 / Gemini 중 하나를 사용자가 직접 고른다** — 자동 폴백은 일부러 만들지 않았다. 두 엔진은 응답 스타일·품질이 달라서, 크레딧이 떨어졌다고 조용히 다른 엔진으로 넘어가면 사용자가 결과 차이의 원인을 알 수 없기 때문이다. 생성 결과에는 항상 어느 엔진으로 만들었는지 표시된다.

- `OPENAI_BASE_URL`은 선택 항목이다. 정식 OpenAI API를 쓰면 비워두면 되고, 학교/회사에서 발급하는 OpenAI 호환 LLM 게이트웨이(예: 경희대 ChatKHU)를 쓴다면 게이트웨이의 base URL을 넣는다. `OPENAI_API_KEY`에는 그 게이트웨이가 발급한 키를 넣는다.
- `OPENAI_MODEL`은 기본값 `gpt-4o-mini`. 게이트웨이가 다른 모델명을 요구하면 여기서 바꾼다.
- `GEMINI_*`는 [Google AI Studio](https://aistudio.google.com/)에서 무료로 발급받는다. Gemini가 OpenAI 호환 엔드포인트를 제공하므로 같은 클라이언트 코드로 호출한다. 기본값은 코드에 있고(`https://generativelanguage.googleapis.com/v1beta/openai/`, 모델 `gemini-flash-latest`), 비워두면 그 값이 쓰인다.
  - ⚠️ 모델명은 실측으로 확정한 것이다. `gemini-2.0-flash`는 무료 티어 쿼터가 0이라 HTTP 429, `gemini-2.5-flash`는 "신규 사용자 지원 종료"로 HTTP 404였고, 항상 최신 flash를 가리키는 공식 별칭 `gemini-flash-latest`만 정상 응답했다. 별칭이라 Google이 실체를 바꾸면 응답 품질이 조용히 달라질 수 있다.

### ECOS_API_KEY

[한국은행 ECOS](https://ecos.bok.or.kr/api/)에서 무료 발급(본인인증 필요). 없어도 매크로 지표 페이지는 동작하지만 한국 CPI/M2는 FRED 미러링 데이터로, 수출액·외환보유액도 FRED로 폴백되고, 경상수지·가계신용·수출증가율(YoY)·한국 CPI 구성항목·한국 기여도 분해는 대응하는 FRED 계열이 없어 안내 메시지만 뜬다.

### DART_API_KEY

[OpenDART](https://opendart.fss.or.kr/)에서 무료 발급. 없으면 (1) 한국 종목의 yfinance 재무 완전 실패 시 대체 표시가 안 되고, (2) "최근 공시 (DART)" 섹션이 비활성화되며, (3) 맨 아래 "DART 원본 재무제표 (실험)" 섹션이 비활성화된다.

### KRX_ID / KRX_PW

[KRX 정보데이터시스템](https://data.krx.co.kr/)의 개인 회원 계정. "투자자별 수급" 섹션(pykrx 기반) 전용이며, 실측 확인 결과 개별종목 투자자별 매매동향 조회는 이 로그인 세션이 있어야 정상 동작한다(없으면 KRX가 로그인 페이지를 돌려줘 파싱이 깨짐). ⚠️ 개인 계정 자격증명이므로 `.env`에만 두고 절대 커밋하지 않는다. 공식 API가 아니라 KRX 웹 로그인을 우회하는 경로라, KRX가 정책을 더 조이면 언제든 막힐 수 있다.

### BLS_API_KEY

[BLS Public Data API](https://data.bls.gov/registrationEngine/)에서 무료 발급. 매크로 페이지의 "CPI 구성 비중 & 기여도"에서 미국 CPI 상대중요도(가중치)를 조회하는 데만 쓰인다. 없으면 그 섹션의 미국 부분만 안내로 대체된다.

### KOFIA_API_KEY

[공공데이터포털](https://www.data.go.kr)에서 "금융위원회_금융투자협회종합통계정보" API를 활용신청해 발급받는다(이미 URL-인코딩된 형태로 발급되며 그대로 넣으면 된다). 매크로 페이지의 "증시 주변자금 / 신용공여"(일별·코스피/코스닥 구분 신용거래융자·증시자금)에만 쓰인다. 없으면 그 섹션이 안내로 대체된다.

### TOSS_CLIENT_ID / TOSS_CLIENT_SECRET

[토스증권 Open API 개발자센터](https://openapi.tossinvest.com/)에서 발급받는 OAuth2 Client Credentials Grant용 앱 키. 발급 시 등록한 IP에서만 토큰이 발급된다. 계좌·주문 관련 API는 이 프로젝트가 쓰지 않는다(리서치 전용 조회성 엔드포인트만 사용). 없어도 앱은 정상 동작하며 다음 기능만 파일럿으로 추가되지 않는다:

- Stock Research "투자자별 수급": 없으면 KRX(거래대금) 소스만 쓰고, 있으면 소스 선택 라디오가 나타나 토스(거래량 기준 + 기관 세부분류)와 비교할 수 있다.
- Stock Research "종목 리스크 지표 (공매도·신용·대차)": 국내 종목 전용, 이 키가 있어야만 섹션이 활성화된다.
- Macro Indicator "한국 국채 수익률곡선": 국고채 2Y~30Y 스냅샷.

### 티커 입력

- 미국 주식: `AAPL`, `MSFT`, `NVDA` 같은 티커 그대로 입력 (달러로 표시)
- 클래스 주식: `BRK.B`, `BF.B`처럼 점 표기로 입력해도 yfinance 표기(`BRK-B`)로 자동 변환한다. ⚠️ "영문자 + 점 + 단일 영문자" 패턴일 때만 변환하므로 `005930.KS` 같은 한국 접미사는 건드리지 않는다.
- 한국 주식: 6자리 종목코드(`005930` 등)를 입력하면 코스피(.KS)/코스닥(.KQ)을 자동 판별 (원화로 표시)
- 한국 종목명(`삼성전자`, `삼성` 등 한글)을 입력하면 이름으로 검색해 6자리 코드를 찾아준다. 후보가 여러 개면 선택 목록이 뜬다 (Stock Research 페이지 전용, 부분일치 지원, 우선주도 검색됨)

### Stock Research (종목 분석)

- **시장 스냅샷** (페이지 진입 즉시 자동 표시): 주요 지수·금리·환율의 최근 시세. 이 섹션만 예외적으로 버튼 없이 자동 조회된다(열자마자 시장 상황 파악이 목적). 지연 시세(약 15~20분)이며 미국장 상태(개장/장전/장후/마감)를 함께 보여준다.
- **회사 개요** (미국 종목): 섹터·산업·직원 수·본사 위치·웹사이트와 yfinance의 사업 서술(`longBusinessSummary`)을 보여준다. 원문은 영문이라 "한국어로 요약" 버튼으로 AI 요약을 생성할 수 있다(버튼 클릭 시에만 호출, 엔진별 캐싱). 필드가 없는 종목은 그 항목만 생략하고, 전부 없으면 섹션 자체를 숨긴다.
- **재무 추이**: 매출과 순이익을 각각 별도 차트로 보여준다(같은 축에 겹치면 매출 규모에 눌려 순이익선이 바닥에 깔리기 때문).
- **밸류에이션**: Peer Group PER/PBR 비교, 연도별 PER/PBR 밴드, 배당수익률·배당성향·ROE.
- **DCF** (제조업 등 비금융업): "성장률 감쇠 사용" 체크박스로 초기→말기 선형 감쇠(2-stage) 모델을 켤 수 있고, "현재 주가에 내재된 성장률"(시장이 요구하는 성장률 역산)과 성장률×요구수익률 민감도 표를 함께 보여준다. "COE 자동제안"을 켜면 요구수익률을 무위험이자율(10년 국채금리 실시간 조회) + 리스크프리미엄(사용자 가정)으로 계산해준다.
- **과거 FCF 증가율**: 연도별 FCF와 전년비 증가율 표, 연평균 증가율(CAGR), 그리고 "과거 실제 / 내 가정 / 시장 내재" 세 성장률 대조. "이 값을 DCF 가정으로 쓰기" 버튼으로 CAGR을 성장률 슬라이더에 반영할 수 있다(감쇠 모드에서는 비활성). ⚠️ 이 섹션은 DCF 성공 여부와 무관하게 항상 표시된다 — 전 구간 FCF가 음수인 적자 성장주야말로 "FCF가 개선 추세인가"가 가장 궁금하기 때문.
- **P/B × ROE 밸류에이션** (은행·보험): 정당 P/B(= ROE / COE)를 현재 P/B와 비교해 괴리율을 낸다. ROE는 단년과 3개년 평균을 둘 다 보여주고(일회성 손익으로 단년 ROE가 튀면 정당 P/B가 통째로 왜곡되므로), 정당 P/B는 3개년 평균 ROE를 우선 사용한다.
- **DDM (배당할인모형)** (은행·보험): Gordon Growth 모형(`D1 / (COE − g)`)으로 주당가치를 계산한다. 과거 배당 CAGR을 실측 앵커로 제시하고 연도별 배당 표를 함께 보여준다(특별배당·배당 삭감 같은 이상치를 사용자가 눈으로 확인하도록). ⚠️ `g ≥ COE`면 발산하므로 계산 불가로 명확히 실패시키고, 무배당 기업은 "DDM 적용 불가"로 안내한다.
- **최근 공시 (DART)** (한국 종목): 조회 기간(1개월/3개월/6개월/1년)과 보고서명 키워드로 필터링, 각 공시는 DART 원문 페이지로 연결된다.
- **최근 공시 (SEC EDGAR)** (미국 종목): 최근 100건을 받아 범주 필터(실적·정기보고 / 중요 사건 / 지분 변동 / 주주총회·기타 / 기타)로 거른다. 기본값은 "실적·정기보고 + 중요 사건"이라 Form 4(임원 지분변동) 홍수가 걸러진 상태로 보인다. 필터 결과가 0건이면 "선택한 유형을 SEC에서 직접 조회하기" 버튼이 나타난다(아래 알려진 한계 참조).
  - **8-K 요약**: 8-K 행의 "AI 요약 생성하기" 버튼으로 본문을 한국어로 요약한다. 실적 발표 8-K는 본문이 표지뿐이고 실제 내용이 첨부(EX-99.1)에 있는 경우가 많아, 색인에서 EX-99.1 유무를 확인해 있을 때만 이어붙인다.
  - **10-K/10-Q 요약**: MD&A(경영진 논의·분석) 섹션만 추출해 요약한다. "MD&A 추출(크기 확인) → 크기 안내 → 진행 확정" 2단계라, 문서가 긴 종목에서 요약 전에 규모를 보고 판단할 수 있다.
- **투자자별 수급 (외국인·기관·개인)** (한국 종목): 최근 20영업일의 일별 순매수 추이(라인 차트)와 기간 누적 합계(매수우위 +/매도우위 −). 기본은 KRX(거래대금) 소스이며, `TOSS_CLIENT_ID`/`SECRET`이 있으면 토스증권(거래량 기준, 파일럿) 소스로 전환하는 라디오가 나타난다 — 토스 소스는 기관 세부분류(금융투자·보험·투신·사모펀드·은행·기타금융기관·연기금)도 함께 보여준다. ⚠️ 두 소스는 단위(거래대금 vs 거래량)가 달라 직접 비교하지 않는다.
- **종목 리스크 지표 (공매도·신용·대차)** (한국 종목, `TOSS_CLIENT_ID`/`SECRET` 필요): 공매도 비중, 신용거래(융자·대주) 잔고, 대차거래 잔고를 각각 독립된 차트/표로 보여준다 — 셋 다 의미가 달라(공매도=하락 베팅, 신용융자=개인 레버리지, 대차=공매도 선행 성격이나 헤지·차익거래 목적도 포함) 절대 섞지 않는다. ⚠️ T+1 지연이 있어 조회 당일 데이터는 다음 거래일에 반영된다. 버튼 클릭 시에만 조회한다(호출 3회).
- **요약 내보내기**: 종목 개요·밸류에이션·DCF 결과를 마크다운으로 보여주고 `.md` 파일로 다운로드한다.

### Screener

기본 대형주 유니버스(미국/한국 약 15개씩, 자유롭게 추가/수정 가능)를 PER/PBR/배당수익률/배당성향/시가총액/통화 조건으로 필터링한다. 배당수익률·배당성향 하한은 한국(KRW)/미국(USD)에 서로 다른 값을 걸 수 있다. "스크리닝 실행" 버튼을 눌러야 데이터를 가져오고, 이후 필터 조작은 재조회 없이 즉시 반영된다.

### Comparison

최대 4개 종목의 PER/PBR/시가총액을 나란히 비교하고, 매출성장률(YoY %)·순이익률(%) 추이를 겹쳐서 본다(통화가 다른 종목의 절대금액을 직접 겹치면 왜곡되므로 비율 지표로 비교).

"DCF 비교" 섹션에서는 모든 비교 종목에 **동일한** DCF 가정(성장률/COE/영구성장률/투영연수)을 적용해 괴리율(%)과 시장 내재 성장률(%)을 나란히 비교한다 — 종목마다 다른 가정을 주면 비교 자체가 무의미해지기 때문. 내재가치·현재가는 참고용으로 각 종목 통화로 표기하되, 비교의 축은 통화 무관한 %지표다. 어느 한 종목의 FCF/발행주식수가 없거나 성장률 역산이 안 되면 그 칸만 사유와 함께 N/A로 표시되고 나머지 종목은 정상 계산된다.

### Macro Indicator

- **개별 지표**: "무엇을 알고 싶은가" 기준 4단 카테고리로 물가를 나눈다 — **물가**(헤드라인: CPI·근원CPI·PCE·근원PCE), **물가 구성**(무엇이 물가를 움직였나: 원계열/계절조정 구성항목), **기저 인플레**(절사평균·중위 등 극단값을 걸러낸 추세), **물가 파급**(생산자물가·실질임금처럼 물가와 연관된 지표). 그 외 금리·고용·성장·통화·재정 지표도 최대한 긴 시계열로 본다. 미국은 3개월 국채·10Y-3M 금리차·하이일드 스프레드·VIX·기대인플레이션·실질금리·달러인덱스를 묶은 "위험지표" 카테고리를 포함한다.
- **한국 특화**: 수출 주도·환율 민감형 경제 특성을 담기 위해 "대외"(경상수지·수출액·외환보유액)와 "가계신용"(가계신용 잔액, 분기별) 카테고리를 ECOS 기반으로 제공한다.
- **지역 연준 제조업 서베이 세부항목** (미국): 라이선스 문제로 FRED에서 삭제된 ISM 제조업 PMI 대신, 필라델피아·뉴욕 등 지역 연준 서베이 세부항목을 지역별로 따로 보여준다(0 기준 확산지수라 전월 대비 포인트 차이로 비교, YoY% 미적용).
- **고용보고서 한눈에 보기** (미국): 매달 첫 금요일 발표되는 고용보고서(Employment Situation) 핵심 지표를 한 표로 본다. 서로 다른 두 조사(가계조사/사업체조사)가 섞여 있음을 구분해 표시하며, 비농업고용 업종별 분해도 제공한다.
- **신용시장 — 하이일드 vs 투자등급 스프레드** (미국): AI 데이터센터 등 대규모 투자의 조달 여건을 신용 사이클 신호로 본다. 둘 다 OAS(%) 동일 단위라 정규화 없이 겹쳐 그린다. "주요 기업 채권 발행 동향"에서는 같은 기업들의 실제 회사채 발행 이력(SEC EDGAR 424B 계열)을 최신순으로 본다.
- **기저 인플레 비교 — 헤드라인·근원·절사평균/중위** (미국): 6개 시리즈(헤드라인·근원 CPI·PCE, 절사평균, 중위)를 전부 12개월 변화율·계절조정(SA)으로 통일해 한 차트에 겹친다 — "특정 품목 때문인지 전반적인지"를 다른 각도에서 보여준다.
- **CPI 구성항목 한눈에 보기**: 미국은 주거비·식품·에너지·근원상품·근원서비스(원계열 NSA), 한국은 지출목적별 대분류를 ECOS로 제공한다. 항목별 최근/전월 YoY를 한 표로 비교한다. ⚠️ 계절조정(SA)과 원계열(NSA)을 한 비교 표 안에 섞지 않는다 — CPI 구성항목은 NSA로, PCE 재화/서비스는 SA로 통일하고 라벨에 명시했다.
- **CPI 구성 비중 & 기여도**: 가중치를 결합해 "이번 달 헤드라인 인플레 중 무엇이 얼마나 밀어올렸나"를 분해한다. 비중은 원 그래프, 기여도(%p)는 막대그래프(음수 기여도도 표시)로 본다. "기여도 기준" 라디오로 YoY(전년동월비)/MoM(전월비)을 전환할 수 있다 — 두 방식은 조정 방식이 나라마다 달라(미국 SA, 한국 NSA) 서로 비교하지 않는다.
  - ⚠️ 이 뷰는 "구성항목 한눈에 보기"와 **다른 항목 집합**을 쓴다. 미국 주거비는 근원서비스에 포함되고, 한국 외식(K01)은 대분류가 아닌 중분류라 그대로 쓰면 이중 계상되거나 층위가 어긋난다. 그래서 미국은 식품+에너지+근원상품+근원서비스 4분할, 한국은 지출목적별 12개 대분류로 배타적·망라적 집합을 별도 정의했다.
  - **자기검증**: 기여도 합계와 헤드라인 YoY(또는 MoM)를 화면에 나란히 표시한다. 둘이 크게 어긋나면 가중치·항목집합·계산 중 뭔가 틀린 것이므로, 오차를 숨기지 않고 드러낸다.
- **증시 주변자금 / 신용공여** (한국, `KOFIA_API_KEY` 필요): 신용거래융자·신용거래대주 잔고(전체/코스피/코스닥)와 증시자금(투자자예탁금 등)을 일별로 본다. ECOS 901Y056(월별·시장 합계)보다 해상도가 높다. ⚠️ 이 API는 갱신이 며칠 늦을 수 있어 "기준일"이 오늘이 아닐 수 있다.
- **한국 국채 수익률곡선** (`TOSS_CLIENT_ID`/`SECRET` 필요): 국고채 2Y·3Y·5Y·10Y·20Y·30Y 수익률을 만기 순으로 이어 곡선 모양을 본다(시계열이 아니라 한 시점의 단면). 10Y-2Y 부호로 정상/역전/평탄 형태를 판정한다.
- **재정**: 국가부채/GDP를 미국·한국 모두 IMF WEO의 일반정부 총부채(GFSM 2001 기준) 계열로 제공한다. ⚠️ 국가부채는 총부채/순부채, 중앙정부/일반정부로 정의가 갈리므로, 양국을 **같은 정의**로 맞추는 것이 비교의 전제다. FRED 시리즈 설명과 IMF 지표 코드(`188N` 접미사)가 양국 동일함을 실측 확인했다. 전용 "한미 국가부채/GDP 비교" 섹션에서는 둘 다 단위가 %라 정규화 없이 원값 그대로 겹쳐 본다(정규화하면 120% vs 50%라는 절대 격차가 사라짐). 연간 데이터라 양국 최신 연도가 다를 수 있어 기준연도를 명시한다.
- **혼합 지표**: CPI 상승률(YoY %)·실질금리·M2/명목GDP·수출 증가율·한미 정책금리차 같은 조합 지표.
- **지표 겹쳐보기**: 단위가 다른 지표 2~3개를 골라 겹치는 기간의 첫 관측치=100으로 지수화해 한 차트에 비교한다.

## 테스트

```bash
pip install -r requirements-dev.txt   # 개발 전용(pytest) — 앱 실행에는 필요 없다
pytest
```

`pytest`만 치면(별도 `PYTHONPATH` 설정 불필요, `pytest.ini`가 처리) 아래를 검증한다:

- **`tests/test_valuation.py`·`test_composite.py`·`test_macro.py`**: `valley/`의 순수 계산 함수 단위테스트(DCF/WACC/CAPM/실효세율/성장률 계산 등). 네트워크를 타지 않아 빠르고 항상 안정적이다.
- **`tests/test_session_keys.py`**: 4개 페이지의 `st.session_state` 키가 서로 겹치지 않는지 정적으로 검사한다(소스를 실행하지 않고 텍스트만 분석). 과거 Comparison 페이지 크래시의 근본 원인이 페이지 간 세션 키 충돌이었어서, 이 회귀를 자동으로 잡아낸다.
- **`tests/test_apptest_regression.py`**: `streamlit.testing.v1.AppTest`로 4개 페이지가 실제로 죽지 않는지 확인한다. "최초 진입(버튼 없이 페이지만 여는 상태)" 케이스를 반드시 포함한다 — 과거 크래시가 정확히 이 케이스를 테스트하지 않아 놓쳤던 것이었다.

⚠️ **API 키(.env) 없이도 전부 통과한다** — 이게 CI에 올릴 수 있는 최소 조건이다. 각 페이지는 키가 없으면 죽는 대신 안내 메시지로 대체하도록 이미 설계돼 있고, 테스트도 그 경로를 확인한다.

기본 실행은 실제 외부 API(yfinance/FRED/ECOS/DART/EDGAR/KRX)를 호출하지 않는다 — 자동 로드되는 유일한 예외(Stock Research 상단의 시장 스냅샷)만 mock 처리한다. 실제 티커를 조회하는 전체 플로우(느리고 네트워크·KRX 로그인 여부에 좌우됨)는 `@pytest.mark.network`로 분리해뒀다:

```bash
pytest -m network      # 전체 플로우만
pytest -m ""           # 마커 필터를 풀고 전부(기본+network) 실행
```

⚠️ AI 요약·해설(`ai_commentary`/`edgar_summary`/`company_summary`)을 실제로 호출하는 테스트는 없다 — "AI 생성하기" 버튼을 누르는 테스트 자체가 없어 API 크레딧이 소모되지 않는다.

## 구조

### 엔트리포인트 / UI

- `app.py` — 엔트리포인트, `st.navigation`으로 페이지 라우팅만 담당
- `views/stock_research.py` — Stock Research (종목 분석)
- `views/screener.py` — Screener (다중 종목 필터링)
- `views/comparison.py` — Comparison (다중 종목 비교)
- `views/macro_indicator.py` — Macro Indicator (매크로 지표)
- `views/_cache.py` — `valley/`의 조회 함수를 `st.cache_data`로 감싸는 캐싱 전용 래퍼 (`valley/`는 Streamlit 의존성 없이 유지). AI 요약 캐시는 **캐시 키에 엔진을 포함**한다 — 안 그러면 엔진을 바꿔 재요약해도 이전 엔진의 결과가 캐시에서 나와, 사용자는 새 엔진 결과라고 믿는데 실제로는 아닌 사고가 난다.
- `views/_charts.py` — Altair 차트 헬퍼. `line_chart_with_markers`는 여러 곳에서 공유하므로 시그니처를 바꾸지 않는다.

> ⚠️ **세션 키 규칙**: `st.session_state`는 페이지별이 아니라 앱 전체 공용이다. 페이지별 접두어(`sr_`/`screener_`/`cmp_`/`macro_`)를 반드시 붙인다. 이 규칙이 없던 시절 Stock Research의 `has_run`과 Comparison의 `has_run`이 충돌해, 한 페이지 상태가 다른 페이지로 새어나가 크래시가 났다.

### 데이터 조회 / 계산 (`valley/`)

- `valley/data.py` — yfinance로 재무·주가 데이터 조회, 한국 종목코드 → 코스피/코스닥 심볼 자동 판별(`resolve_ticker`).
  - `resolve_ticker`의 종목 유효성 판별은 `(longName or shortName) and quoteType == "EQUITY"`다. `longName`만 보던 시절, 야후가 정식명 없이 약칭만 주는 종목(예: 295310 에이치브이엠 → `shortName: "HVM"`)이 데이터가 멀쩡한데도 "찾을 수 없음"으로 튕겼다. 이름 조건을 아예 없애지는 않는다 — 6자리 코드가 우연히 겹치는 펀드/지수가 통과하는 걸 막아야 한다.
  - 클래스 주식 정규화: `^[A-Z]+\.[A-Z]$` 패턴만 점→하이픈으로 바꾼다. `BRK.B`는 조회 실패, `BF.B`는 더 나쁘게 엉뚱한 MUTUALFUND로 **오매칭**되는 것을 실측 확인했다(실패보다 조용한 오매칭이 위험하다).
  - FCF는 현금흐름표의 **`Free Cash Flow` 행을 우선** 사용하고, 없으면 기존 `OCF − Capex` 방식으로 폴백한다. 은행(JPM/BAC 등)은 제조업식 설비투자 개념이 희박해 야후가 `Capital Expenditure` 행을 아예 주지 않아 계산이 실패했다. ⚠️ 우선순위를 바꾸기 전에 AAPL/MSFT/TSLA/삼성전자/KB금융/신한지주의 두 방식 값을 연도별로 전부 대조해 diff=0.0(완전 동일 정의)임을 확인했으므로, 기존 종목의 값은 하나도 바뀌지 않는다.
  - 주가 추이(`get_price_history`)는 PER/PBR 계산과 달리 배당/분할 조정 종가(auto_adjust 기본값)를 그대로 쓴다 — 보기 좋은 추이가 목적이라 조정 종가가 맞다.
  - `build_snapshot`은 회사 개요용 필드(`employees`/`website`/`city`/`state`/`country`/`business_summary`)를 함께 반환한다(`.info`를 추가로 재호출하지 않고 이미 받은 dict를 확장).
- `valley/peers.py` — Peer Group 목록, PER/PBR/배당수익률/배당성향/ROE 스냅샷·연도별 밴드, `bvps`, `get_roe_history`(3개년 평균 ROE용), `get_annual_dividend_history`(연도별 배당 합산), 밸류에이션 표 포맷터.
  - PER/PBR은 모든 종목을 최근 확정 회계연도(FY) 재무제표로 직접 계산해 통일한다(Yahoo `trailingPE` 등 TTM 지표는 미국은 TTM, 한국은 FY로 기준이 섞이므로 쓰지 않음). Fwd PER만 Yahoo `forwardPE`를 그대로 사용한다.
  - 배당수익률은 `info["dividendYield"]`가 이미 퍼센트 값(예: 0.32 = 0.32%)으로 오는 것을 실측 확인해 100으로 나눠 통일했고(그대로 쓰면 100배 부풀려짐), info에 없으면 배당 지급 이력 최근 4회 합으로 폴백한다.
  - `get_roe_history`는 적자 연도를 평균에서 **제외하지 않는다** — ROE는 이미 정규화된 비율이라 FCF처럼 부호 때문에 평균이 성립 안 하는 문제가 없고, 오히려 손실 난 해를 빼면 그 은행의 실제 리스크를 과소평가하게 된다.
  - `get_annual_dividend_history`는 진행 중인 올해를 제외한다(분기배당 기업의 미완결 지급분이 섞이면 그 해 배당이 실제보다 적게 잡힘).
- `valley/valuation.py` — 밸류에이션 순수 함수 모음.
  - `simplified_dcf`: OCF(이자비용 차감 후) 기반 FCF를 COE로 할인해 Equity Value를 직접 산출한다. 순차입/상환 효과는 반영하지 않는다. `growth_rate_terminal`을 지정하면 1년차→N년차 성장률이 선형 감쇠(2-stage)하고, 미지정 시 기존 단일 성장률과 수학적으로 동일하다(하위호환).
  - `implied_growth_rate`: 현재 주가를 정당화하는 단일 성장률을 이분법으로 역산한다(해가 없으면 `ImpliedGrowthNotFoundError` — 이건 에러가 아니라 "현재가가 상식적 성장률 범위 밖"이라는 정보다).
  - `sensitivity_grid`: 성장률×COE 격자별 내재가치/괴리율(항상 단일 성장률 기준).
  - `fcf_growth_history` / `dividend_growth_history`: 연도별 YoY와 CAGR. ⚠️ 전년 값이 0 이하면 YoY는 수학적으로 무의미하므로 "계산 불가"로 표기하고 숫자를 만들지 않는다. CAGR은 시작·종료가 둘 다 양수일 때만 계산한다.
  - `justified_pbr(roe, coe)`: 정당 P/B = ROE / COE. 성장 포함형 `(ROE−g)/(COE−g)`은 일부러 쓰지 않았다 — 변수가 늘고 `COE−g`가 0 근처면 발산한다.
  - `gordon_ddm(dps, g, coe)`: `g ≥ COE`(발산), DPS ≤ 0(무배당), COE ≤ 0을 모두 명시적으로 실패시킨다.
  - `suggest_coe`: 무위험이자율(USD는 FRED `DGS10`, KRW는 `IRLTLT01KRM156N`)을 실측 조회해 사용자가 정한 리스크 프리미엄과 더한 COE를 제안한다 — ERP는 무료 데이터로 신뢰성 있게 추정할 방법이 없어 항상 사용자 가정치로 둔다.
- `valley/market_snapshot.py` — Stock Research 상단의 "시장 스냅샷"(주요 지수·금리·환율) 전용. 이 모듈만 예외적으로 페이지 진입 즉시 자동 조회되도록 설계됐고(다른 조회는 전부 버튼 클릭 시에만), 대신 짧은 ttl(5분)로 캐싱해 호출 부담을 억제한다. `yf.download` 대신 `yf.Tickers(...).fast_info`를 쓴다(시장별 거래일이 달라 배치 다운로드는 날짜 정렬이 어긋날 수 있음을 실측 확인).
- `valley/formatting.py` — 통화별 금액(USD `$`, KRW `₩`), PER/PBR 배수, 비율(%) 표시
- `valley/report.py` — 분석 결과를 마크다운 요약 문자열로 변환하는 순수 함수. 계산된 값만 포맷팅하며 숫자를 새로 만들어내지 않는다

### 외부 데이터 소스 (`valley/`)

- `valley/macro.py` — FRED(공개 CSV, 키 불필요) + 한국은행 ECOS로 매크로 지표 조회. `INDICATORS` 카탈로그에 국가별/카테고리별 지표를 등록한다.
  - `get_ecos_series`는 월별(M)·분기별(Q)·연간(A) 세 주기를 지원한다(가계신용이 분기 데이터라 확장 — ECOS는 주기마다 조회 기간/응답 날짜 형식이 달라 `_ecos_period_bounds`/`_ecos_parse_time`으로 분기했고 기존 월별 지표 동작은 그대로 보존된다).
  - ECOS 전용 지표(경상수지·가계신용·CPI 구성항목)는 FRED 폴백을 **일부러 등록하지 않았다** — 후보 FRED 계열이 전부 "GDP 대비 %"라 원계열(절대액)과 단위가 안 맞았기 때문. 단위가 다른 폴백을 조용히 끼워넣는 것보다 명확히 실패하는 편이 안전하다.
  - `get_indicator_series`는 `fred_id`가 없는 ECOS 전용 지표에서도 죽지 않는다.
  - `normalize_indexed()`는 첫 관측치=100으로 지수화하는 순수 함수(겹쳐보기용).
- `valley/composite.py` — 파생 지표 계산. `yoy_percent(series)`는 구성항목마다 개별 혼합지표를 등록하지 않도록 만든 범용 함수다(기존 CPI YoY도 이걸 재사용).
  - 한국 명목GDP(FRED `NGDPSAXDCKRQ`)는 단위가 M2(ECOS, 십억원)와 달라 1000으로 나눠 맞춘다(시리즈에 단위 표기가 없어 비율값을 역산해 확인). 이 보정은 ECOS 기준 역산이라 한국 M2/GDP는 `ECOS_API_KEY`가 없으면 계산을 아예 막는다.
  - 수출 증가율은 KR_EXPORTS(통관기준 수출금액) 원계열이 **월중 값(누적 아님)**임을 연간 합계와 대조해 검증한 뒤 `pct_change(12)`로 계산한다.
  - CPI 기여도는 `(가중치 / 100) × YoY`로 계산하고, 합계와 헤드라인 YoY를 함께 반환해 화면에서 오차를 보이게 한다.
- `valley/bls.py` (또는 `macro.py` 내 BLS 조회부) — CPI 상대중요도(가중치) 조회.
  - BLS 공개 API의 "One or More Series with Optional Parameters"(POST)에 `aspects: true`와 등록키를 넣어 조회한다. flat 파일 경로(`download.bls.gov`)도 시도했으나 봇 정책으로 403이라 API를 채택했다.
  - ⚠️ aspect 필드 구조는 `aspect_type: "I1"`이 아니라 `{"name": "Relative Importance", "value": "13.447"}`다(실측으로 정정).
  - ⚠️ 상대중요도는 **매월 바뀐다**. 지출 가중치에 이후의 상대 가격변동을 곱한 값이라 가격이 움직이면 중요도도 따라 움직인다("연 1회 갱신"이 아니다).
  - ⚠️ FRED ID와 BLS series ID는 다르다(`CPIAUCNS` ↔ `CUUR0000SA0`, `CPIUFDNS` ↔ `CUUR0000SAF1`, `CPIENGNS` ↔ `CUUR0000SA0E`). 매핑 후 지수값이 소수점까지 일치하는지 대조해 확인했다.
  - ⚠️ FRED의 `RIW*` 시리즈("Relative Importance Weights")는 연준 G.17 **산업생산지수**의 가중치이지 CPI 가중치가 아니다. 이름이 비슷해 혼동하기 쉽다.
- `valley/krx.py` — 한국 종목명 → 6자리 코드 검색(`resolve_ticker`의 "앞단"). pykrx의 공개 함수 `get_market_ticker_list()`는 (설치 버전 1.2.8 기준) KRX 로그인 세션을 요구하도록 바뀌어 있어 로그인 없이는 "LOGOUT" 오류로 실패하는 것을 직접 재현 확인했다. 대신 로그인 없이 동작하는 `StockTicker`(pykrx 내부 모듈)에서 전체 상장종목 목록을 가져온다 — 공개 API가 아니라 향후 pykrx 버전이 바뀌면 깨질 수 있다.
- `valley/supply.py` — 개별종목 투자자별 순매수 조회(pykrx `get_market_trading_value_by_date`). KRX 로그인이 필요함을 실측 확인했고, 로그인 정보가 없거나 무효하면 pykrx가 예외 없이 빈 DataFrame을 반환하므로 호출 전에 `KRX_ID`/`KRX_PW` 존재를 먼저 확인해 명확한 메시지를 준다. pykrx가 이미 "기관합계/기타법인/개인/외국인합계/전체" 대분류로 주는 것을 확인해 그대로 외국인/기관/개인 3분류로 쓰고, 항상 0인 "전체"(매수−매도 검산용)와 "기타법인"은 버린다(버린 값까지 합산해 정확히 0으로 떨어지는 것을 확인 — 누락 없음). 반환값은 일별(누적 아님) 원화 금액이라 기간 누적은 이 시계열을 그대로 합산한다(`summarize_net_trading`).
- `valley/toss.py` — 토스증권 Open API(리서치 조회 전용, 계좌·주문 API는 절대 호출 안 함). 국내 종목 투자자별 수급(거래량 기준, KRX와 단위가 달라 절대 안 섞음), 기관 세부분류, 공매도·신용거래·대차거래 리스크 지표, 국채 수익률곡선 스냅샷을 제공한다. OAuth2 Client Credentials 토큰을 스레드 안전하게 캐싱하고 만료 5분 전에 미리 재발급한다.
- `valley/kofia.py` — 금융투자협회(KOFIA) 신용공여·증시자금(공공데이터포털 경유). ECOS 901Y056(월별·시장 합계)과 달리 일별·시장별(코스피/코스닥) 해상도를 준다 — 실측 대조 결과 ECOS 월말값과 정의상 동일함을 확인했다. ⚠️ 응답이 기본 XML이고(`_type=json`을 무시함), 갱신이 KOFIA 공식 웹보다 며칠 늦을 수 있다.
- `valley/dart.py` — OpenDART 원본 재무제표·공시 목록 조회. 세 용도: (1) yfinance 재무 완전 실패 시 자동 폴백, (2) "DART 원본 재무제표 (실험)"에서 yfinance와 대조, (3) "최근 공시 (DART)".
  - `bgn_de`는 항상 오늘 기준으로 역산해 명시적으로 넣고(비워두면 DART가 좁은 기본 범위만 줄 수 있음), 해당 기간에 공시가 없는 것(`status="013"`)은 에러가 아니라 빈 리스트로 정상 반환해 조회 실패와 구분한다.
  - corp_code 매핑은 `st.cache_data`뿐 아니라 루트의 `.dart_corp_code_cache.json`에도 저장해 앱 재시작 후에도 재사용한다(.gitignore 처리됨).
  - 연결재무제표(CFS)를 우선 조회하고 없으면 별도(OFS)로 폴백하며, 어느 쪽을 썼는지 화면에 표시한다.
  - 계정 매칭은 `account_id`(IFRS 표준/DART 확장 분류코드)를 우선으로 쓰고 한글 계정명은 폴백으로만 쓴다 — 같은 한글 계정명("지배기업의 소유주지분")이 같은 응답 안에서 서로 다른 두 항목(순이익 귀속분 vs 포괄손익 귀속분)을 가리키는 걸 실측 중 발견해서다. 당기순이익은 지배주주 귀속분을 우선 매칭한다(yfinance의 Net Income과 대조해보니 총계가 아니라 이 값과 일치 — 3사×3개년×3항목 전부 0.0000% 일치 확인).
- `valley/edgar.py` — SEC EDGAR 공시 조회.
  - ⚠️ **User-Agent 헤더에 연락처를 반드시 넣어야 한다**. 없으면 HTTP 403(실측 확인). 모든 요청에 `_HEADERS`를 강제 적용한다.
  - 티커→CIK 매핑은 `company_tickers.json`에서 만들고, `cik_str`이 zero-pad 안 된 정수로 오므로 `zfill(10)`으로 변환한다. 로컬 파일 캐시(`.edgar_ticker_cik_cache.json`, .gitignore 처리)와 `st.cache_data`로 이중 캐싱.
  - 공시 목록은 `submissions/CIK{10자리}.json`에서 가져온다. ⚠️ `filings.recent`는 "공시별 객체 배열"이 아니라 **컬럼별 배열**(form/filingDate/accessionNumber가 각각 같은 길이의 리스트)이라 인덱스로 묶어 파싱한다.
  - `FORM_CATEGORIES` / `categorize_form()` — form type을 범주로 묶는다. 어느 form도 누락되지 않도록 미매핑은 전부 "기타"로 떨어뜨린다.
  - `get_filings_by_type(cik, form_type)` — `browse-edgar?type=X&output=atom`으로 특정 유형만 직접 조회한다. ⚠️ Atom XML의 `filing-date`/`filing-type`/`filing-href` 같은 필드가 전부 Atom 네임스페이스 안에 있어 `ElementTree`에 네임스페이스를 명시해야 한다.
  - `get_mda_section_text()` — 10-K는 Item 7(~7A/8 직전), 10-Q는 Part I Item 2(~3/4 직전)를 추출한다. ⚠️ 목차(TOC) 오탐을 피하는 기준은 **"항목번호 뒤에 정식 제목이 같은 줄에 이어지는가"**다 — 목차는 항목번호·제목·페이지번호가 서로 다른 줄에 흩어져 있다. 위치 기반(앞부분 제외, 두 번째 등장) 방식은 본문 내 교차 참조("Part II, Item 8 참조")까지 오탐하는 것을 실측 확인해 기각했다. 추출 실패 시 전체 문서로 폴백하지 않고 명확히 실패시킨다(비용 폭증 방지).
  - 8-K 본문 추출 시 iXBRL 문서의 `<div style="display:none">` 안에 숨은 잡음(체크박스 플래그 등 수백 자)을 제거한다.
- `valley/kosis.py` — ⚠️ **검증 전용, 카탈로그/UI 어디에도 연결되지 않음**(2026-08 KOSIS 검증 라운드 산출물). 한국 CPI를 ECOS 대신 통계청 KOSIS OpenAPI로 받을 수 있는지 확인하기 위한 모듈이다. 값은 ECOS 901Y009와 156개 데이터포인트 전부 일치 확인했지만 가중치는 API로 제공되지 않아(xlsx 다운로드만 존재), 당장 카탈로그를 전환하지는 않았다 — 다음 CPI 발표일 실측(발표 당일 반영 시차 비교)까지가 조건이다.

## 주의사항

본 도구는 정보 제공 목적이며 투자자문이 아닙니다. 전부 무료/비공식 데이터 소스이며, PER/PBR/재무 추이는 trailing(과거 확정 실적) 기준입니다. Fwd PER만 Yahoo가 제공하는 컨센서스 기반 예외입니다. DCF는 순차입/상환을 반영하지 않는 근사치라 자본구조가 크게 바뀔 기업일수록 오차가 커질 수 있고, 결과는 입력한 가정치에 따라 크게 달라지므로 참고용으로만 활용하세요. AI 요약·해설은 생성 모델의 출력이므로 중요한 판단 전에는 반드시 원문을 확인하세요.

## 알려진 한계

### 구조

- **저장소 없음**: DB/파일 캐시가 없어 화면을 그릴 때마다 실시간으로 외부 API를 호출한다(`st.cache_data`는 프로세스 재시작 시 사라지는 인메모리 캐시). 예외적으로 DART corp_code와 EDGAR CIK 매핑만 로컬 JSON 파일로 캐싱한다.
- **Screener는 전체 시장 스크리닝이 아님**: `DEFAULT_UNIVERSE`에 하드코딩된 30개 종목(자유 편집 가능) 안에서만 필터링한다.
- **pandas가 2.3.3으로 고정됨**: pykrx 1.2.8이 `pandas<3.0`을 요구한다. 이 프로젝트 코드는 2.3.3에서 회귀 없이 동작 확인했지만, 3.x로 올리려면 pykrx 쪽 대안을 먼저 찾아야 한다.

### 밸류에이션

- **금융업 판별은 industry 문자열 접두어에 의존한다**: `Banks - *` / `Insurance - *` 형식만 매칭한다. yfinance 섹터(`Financial Services`)로 판별하던 시절 비자/마스터카드(`Credit Services`)까지 잡혀 P/B×ROE가 뜨고 DCF에 "부적합" 경고가 붙었는데, 이들은 자산이 가벼워 오히려 DCF가 잘 맞는다. ⚠️ 다만 "Insurance Brokers"(수수료 기반 중개)가 제외되는 건 이 하이픈 형식이 아니라서 생기는 **부수 효과**이지 의도적 판단이 아니다. yfinance가 표기를 바꾸면 조용히 포함될 수 있다.
- **industry가 없는 종목은 비금융으로 간주한다**: sector 폴백을 두면 위의 오탐이 되살아나므로 일부러 두지 않았다.
- **P/B×ROE는 현재 ROE가 지속된다는 가정 위에 있다**: 일회성 손익으로 ROE가 튀면 정당 P/B가 통째로 왜곡된다. 단년/3개년 평균을 함께 표시하는 이유다.
- **DDM 배당 CAGR이 COE를 초과하면 앵커로 쓸 수 없다**: 예컨대 JPM은 최근 배당 성장률이 COE보다 높아 슬라이더 상한을 넘으므로 기본값으로 폴백된다. 이 폴백 사실 자체가 정보("이 은행은 배당을 요구수익률보다 빠르게 늘려왔다")인데 지금은 화면에 드러나지 않는다.
- **한국 배당 이력에 캘린더 아티팩트가 있다**: 배당 지급시점 정책 변경 탓에 특정 연도 배당이 급감/급증한 것처럼 보이는 종목이 있다(예: KB금융). 연도별 배당 표를 함께 보여주므로 눈으로 확인할 수 있고, CAGR은 시작/종료 연도만 쓰므로 중간 왜곡에 흔들리지 않는다.
- **한국 종목의 `sharesOutstanding`이 우선주를 포함/제외 중 어느 쪽인지 미검증.**
- **PER/PBR 밴드**: 연 4~5개 점의 스냅샷이며 일별 롤링 밴드가 아니다.
- **Fwd PER은 Yahoo 원본값 그대로**: 자체 계산·검증 로직이 없고, 애널리스트 커버리지가 없는 종목은 N/A다.
- **배당수익률 폴백의 "4회 = 1년" 가정**: info에 배당 데이터가 없을 때 최근 4회 합으로 근사하는데, 반기·월배당 기업에서는 어긋날 수 있다.

### 공시

- **EDGAR "최근 N건 + 범주 필터"는 발행량이 압도적인 종목에서 한계가 있다**: JPM은 최근 100건(1000건까지 확인해도)이 전부 424B2/FWP(구조화채권 발행서류)라 정기보고서가 목록에 잡히지 않는다. 이 경우를 위해 "선택한 유형을 SEC에서 직접 조회하기" 버튼(form-type 직접 조회)을 두었고, 범주당 핵심 1~2개 유형만 조회해 호출 폭증을 막는다.
- **정정본(`10-K/A`, `10-Q/A`)의 MD&A 요약은 지원하지 않는다**: 정정본은 고친 부분만 담아 "Item 7"이 아예 없는 경우가 있다(TSLA 사례 실측).
- **MD&A 추출은 미국식 Item 구조에 의존한다**: 회사마다 HTML이 달라도 목차/본문 조판 차이로 구분하지만, 표준을 크게 벗어난 문서에서는 실패할 수 있다(그때는 폴백 없이 명확히 실패).
- **DART 공시는 목록 + 원문 링크까지만 지원한다**: 한국 공시 본문 요약은 아직 없다(EDGAR 쪽 파이프라인을 적용할 여지는 있음). 한 번에 최근 30건까지만 가져온다.
- **DART 폴백은 "yfinance 재무 완전 실패"에만 적용된다**: yfinance가 일부라도 값을 주는 경우는 폴백하지 않는다 — 기존 값을 조용히 DART로 바꿔치기하면 "당기순이익 총계 vs 지배주주 귀속분" 같은 정의 차이가 예고 없이 섞여들 위험이 있어서다.

### 수급 / 시세

- **KRX 투자자별 수급은 개인 계정이 있어야 동작한다**: 공식 API가 아니라 웹 로그인 세션을 우회하는 경로다. 외국인/기관/개인 3분류까지만 제공하고(기관 세분화 없음), 최근 20영업일 고정이며 기간 조절 UI는 없다. `TOSS_CLIENT_ID`/`SECRET`이 있으면 로그인 없이도 토스증권 소스(거래량 기준 + 기관 세분화)로 대체할 수 있으나, 두 소스는 단위가 달라 값을 직접 비교할 수 없다. 미국은 어느 소스로도 일별 투자자별 순매수 공개 데이터가 없어 지원하지 않는다.
- **토스증권 Open API는 비공식 파일럿 취급**: 계좌·주문 API는 이 프로젝트가 쓰지 않지만, 시세/수급/리스크 지표 엔드포인트도 공식 안정성 보장 문서가 충분하지 않다. 종목 리스크 지표(공매도·신용·대차)는 T+1 지연이 있고, 국채 수익률곡선은 정확한 기준 시각이 응답에 없어 최근 거래일 종가로 추정한다.
- **실시간/시간외 시세는 지원하지 않는다**: yfinance는 미국 프리/애프터마켓 필드(`marketState`, `preMarketPrice`, `postMarketPrice`)를 주지만 한국 시간외는 `marketState`만 알려주고 가격은 주지 않는다(실측 확인). 넥스트레이드(NXT) 시세도 야후·pykrx 어느 쪽에도 없어, 보려면 증권사 API가 필요하다 — 그런데 그쪽은 ActiveX/이벤트 루프 기반이라 Streamlit의 재실행 모델과 구조적으로 맞지 않는다.

### 매크로

- **CPI 기여도 합계와 헤드라인 YoY는 정확히 일치하지 않는다**: "현재월 가중치 × YoY"는 근사식이고 BLS의 엄밀한 계산은 직전 기준시점 가중치와 지수비를 쓴다. 오차를 숨기지 않고 화면에 합계와 헤드라인을 나란히 표시한다.
- **CPI 구성 비중/기여도 뷰는 카탈로그와 다른 항목 집합을 쓴다**: 배타성 때문이며, 두 곳의 항목이 다른 것은 의도된 설계다.
- **달러인덱스(`US_DOLLAR`, FRED `DTWEXBGS`)는 DXY가 아니다**: Fed의 무역가중 광의 달러지수로 2006년 1월=100 기준이라 최근 120대에서 움직인다 — "달러가 20% 고평가"라는 뜻이 아니다.
- **하이일드 스프레드가 낮을 때는 역사적 저점 근처일 수 있다**: 추가 시점(2026-07) 값이 약 2.7%로 통상 언급되는 3~8%보다 낮다. 데이터 오류가 아니라 신용시장이 이례적으로 잠잠한 시기로 해석해야 한다.
- **국가부채/GDP는 연간 데이터라 양국 최신 연도가 다를 수 있다**: IMF 발표 시차 때문이며, 기준연도를 표에 명시한다.
- **KOFIA 증시 주변자금/신용공여는 갱신이 며칠 늦을 수 있다**: 실측 결과 API의 최신 관측치가 KOFIA 공식 웹 화면보다도 2영업일 이상 오래됐던 사례가 있었다 — 화면의 "기준일"이 항상 오늘은 아니다.
- **한국 CPI는 ECOS 단일 소스에 의존한다**: 통계청 KOSIS를 대안으로 검증했고(값은 완전 일치, 가중치는 API 미제공) 카탈로그 전환은 아직 하지 않았다 — `valley/kosis.py` docstring 참고.
- **한국 종목명 검색은 pykrx 비공개 모듈에 의존한다**: pykrx 버전이 바뀌면 깨질 수 있다.

### AI

- **회사 개요는 미국 종목에만 노출된다**: 판별을 `currency != "KRW"`로 하므로, 향후 일본·유럽 종목을 다루면 그쪽도 "미국"으로 분류된다(동작은 하지만 의도와 다름). ⚠️ 한국 종목에도 `longBusinessSummary`가 영문으로 존재하는 것은 실측 확인했다(삼성전자 1,528자, HVM 1,083자) — 한국 회사 개요는 DART 본문 파싱 없이도 상당 부분 가능하다.
- **AI 요약은 항상 버튼 클릭 시에만 생성된다**: 자동/일괄 요약은 크레딧 폭증을 막기 위해 일부러 만들지 않았다.
- **문서가 너무 길면 잘라서 요약한다**: 잘렸다는 사실을 결과에 명시한다.
